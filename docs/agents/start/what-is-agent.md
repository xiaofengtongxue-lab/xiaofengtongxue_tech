# AI Agent 到底是什么：跟着一个任务走完闭环

这篇写给第一次接触 Agent 的读者。你不需要会写代码，也不用打开终端。读完以后，你应该能看懂一款 AI 产品是在“回答问题”，还是在“进入环境、调用工具、根据结果继续做事”。

先别背定义。假设你的电脑里有几十份会议记录、项目方案和临时笔记，你对 AI 说：

> 帮我盘点这个文件夹，找出没有处理的 TODO，整理成一份报告。不要改原文件。

如果它只是一个聊天模型，它只能根据你粘贴进对话的内容回答。它看不到文件夹，也不知道真实文件有多少。就算回复“已经整理好了”，这句话仍然只是一段文本。

Agent 多做了什么？它会进入一个循环。

## 第一步：先看真实情况

它不会一上来编报告，而是先问环境：“这个目录里到底有哪些文件？”

应用程序收到这个决定后，真正执行“列出文件”的工具，把路径、大小和类型返回给模型。现在模型得到的不是猜测，而是一份可检查的观察结果。

这里有个很重要的边界：**模型提出调用工具，真正执行工具的是应用程序。** 模型不能只靠一句话穿过你的硬盘、数据库或邮箱。

## 第二步：根据反馈决定下一步

看到文件列表后，模型可能发现里面有三份文本，于是决定搜索 `TODO` 和 `FIXME`。搜索工具返回真实路径和行号，它再挑必要的文件读取，而不是把整个硬盘一次性塞进上下文。

上一轮结果会改变下一轮行为，这就是 Agent 和固定问答最大的区别：

```text
聊天：问题 → 回答

Agent：目标 → 观察 → 决定 → 行动 → 读取结果
                             ↑              ↓
                             └──── 继续 ────┘
```

## 第三步：不是模型说完成，就算完成

报告写出来以后，程序还会检查：

- 文件总数是不是跟目录一致；
- 报告引用的路径是不是真的存在；
- 必需章节有没有缺失；
- 原文件有没有被修改；
- 正式发布是不是经过人工确认。

模型说“完成了”，只能表示它认为可以停下。真正的完成条件应该由任务本身决定。

## 现在可以给 Agent 下定义了

**AI Agent 是一个在明确目标和边界内，能够反复观察环境、决定下一步、调用工具、读取反馈，并持续推进到验收或停止条件的系统。**

或者说，聊天模型主要负责“说什么”，Agent 系统还要处理“接下来做什么、谁来执行、结果怎样确认”。

一个最小 Agent 至少有五样东西：

| 部分 | 大白话解释 | 资料盘点例子 |
| --- | --- | --- |
| 目标 | 到底要完成什么 | 找出待办并生成报告 |
| 模型 | 判断下一步 | 决定先列文件还是搜索 |
| 工具 | 接触真实环境 | 列目录、读文件、写草稿 |
| 状态 | 记住任务现场 | 已读文件、错误、待确认动作 |
| 验收与边界 | 决定能不能继续、何时停止 | 路径限制、最大轮次、报告验证 |

少了模型，它可能只是自动化脚本；少了工具，它可能只是多轮聊天；少了边界和验收，它可能会动，但很难让人放心。

## Tool、Workflow 和 Agent 别混在一起

这三个词经常同时出现，可以用一个办公室场景来分：

- **Tool 是动作**：打开一份文件、查询一条订单、发送一封邮件。
- **Agent 是现场决策者**：看当前结果，决定下一步调用哪个 Tool。
- **Workflow 是流程负责人**：规定身份校验必须先做、付款必须审批、结束后必须留日志。

真实生产系统通常不是“全自动 Agent”，而是外层固定 Workflow 管住必经步骤，内层 Agent 处理无法提前穷举的判断。

## 什么任务值得用 Agent

满足下面四个条件时，Agent 比一次聊天更有价值：

1. **过程不止一步**：做完第一步才能知道第二步是什么。
2. **需要真实工具**：要查文件、数据库、网页、代码或业务系统。
3. **中间会出现反馈**：搜索可能为空、测试可能失败、权限可能不足。
4. **结果可以验收**：文件能打开、测试能运行、来源能核对、业务状态能查询。

如果任务只是改写一句话、翻译一小段文本、按固定公式计算，普通模型调用或确定性程序通常更省事。

## Agent 不是一个“数字员工”承诺

把 Agent 说成“像员工一样什么都能做”，听起来很直观，却会遮住三个事实：

- 多步骤任务中，每一步的错误都可能影响后面；
- 外部资料可能包含恶意指令，诱导它越权；
- 付款、删除、发送和发布等动作不能只靠模型自己判断。

所以靠谱的 Agent 教程不会只展示成功 Demo，还要讲停止条件、权限、检查点、人工确认和评测。这些内容会在 B、C 两条路线里逐步补齐。
