# AI Agent 和普通聊天有什么区别？跟一个任务走完就懂了

你跟 AI 聊过天，这没问题。但让它干一件真事试试——比如"帮我把这个文件夹里所有没处理的 TODO 整理成报告"——它就卡住了。聊天模型只能根据你贴进去的内容回答，看不到你的文件夹，也不知道里面有多少文件。就算回你一句"整理好了"，也只是段文字，不是真的做了。

Agent 不一样。你给它同样的任务，它会自己一步步来：先看目录里有啥、搜关键词、读文件、写草稿，中间哪步出错了还会自己调整。

下面跟着这个任务走一遍，你就懂了。

## 它不猜，而是先去看一眼目录

它不会一上来编报告，而是先问环境："这个目录里到底有哪些文件？"

这里得先解释一件事：大模型本身只是一个 AI 服务，运行在云端。它能听懂你的话、能分析该做什么，但它跟你的电脑是隔开的——它发不出"打开文件""搜索目录"这种系统指令。所以 Agent 里除了模型，还包了一层程序——它的工作很单纯：模型说做什么，它就去做，做完把结果告诉模型。

所以，模型只能说想做什么，真正动手的是那层程序。它收到"列目录"这个决定，去执行，把路径、大小、类型都拿回来。模型手里不再是猜测，而是一份可以核对的观察结果。

这就是 Agent 最关键的一道边界：**模型动脑，程序动手。** 模型一句话穿不透你的硬盘、数据库或邮箱。

## 看完结果，再决定下一步

看到文件列表，模型发现有 .md 和 .txt，决定先搜 `TODO` 和 `FIXME`。搜索结果回来——真实路径、行号都在。它再挑必要的文件读，而不是把整个硬盘塞进上下文。

上一轮结果改变下一轮行为。这就是 Agent 和固定问答的分水岭：

到这里你其实已经看完 Agent 最核心的工作方式了。上面这三步——先观察、再决定、再行动——在业界有一个专门的名字，叫 **ReAct**（Reasoning + Acting，推理加行动）。不用刻意去记这个词，你只需要知道：以后看到各种 Agent 框架、论文里提 ReAct，就是指这个循环。不同的实现会在上面加记忆、加规划、加多轮反思，但骨架就是它。

## 模型说“好了”不算，程序验了才算

报告写出来以后，程序还会检查：

- 文件总数是不是跟目录一致；
- 报告引用的路径是不是真的存在；
- 必需章节有没有缺失；
- 原文件有没有被修改；
- 正式发布是不是经过人工确认。

模型说"完成了"，只代表它自己觉得可以停。真正的完成条件，是任务说了算。

## 现在可以给 Agent 下定义了

**AI Agent 是一个在明确目标和边界内，能够反复观察环境、决定下一步、调用工具、读取反馈，并持续推进到验收或停止条件的系统。**

一句话版：聊天模型管"说什么"，Agent 系统管"下一步做什么、谁来执行、怎么确认"。

一个最小 Agent 至少有五样东西：

| 组成 | 干什么的 | 放在这个任务里 |
| --- | --- | --- |
| 目标 | 到底要完成什么 | 找出待办并生成报告 |
| 模型 | 判断下一步 | 决定先列文件还是搜索 |
| 工具 | 接触真实环境 | 列目录、读文件、写草稿 |
| 状态 | 记住任务现场 | 已读文件、错误、待确认动作 |
| 验收与边界 | 决定能不能继续、何时停止 | 路径限制、最大轮次、报告验证 |

缺模型，它退化成一个脚本。缺工具，它只是多轮聊天。缺边界和验收，它能动，但你不放心。

## Tool、Workflow 和 Agent 别混在一起

这三个词经常一起出现。用一个办公室场景就能分清：

- **Tool 是动作**：打开一份文件、查询一条订单、发送一封邮件。
- **Agent 是现场决策者**：看当前结果，决定下一步调用哪个 Tool。
- **Workflow 是流程负责人**：规定身份校验必须先做、付款必须审批、结束后必须留日志。

真实系统很少是"全自动 Agent"。更常见的是：外层 Workflow 管住必经步骤，内层 Agent 处理没法提前穷举的判断。

## 什么任务值得用 Agent

满足下面四个条件时，Agent 比一次聊天更有价值：

1. **过程不止一步**：做完第一步才能知道第二步是什么。
2. **需要真实工具**：要查文件、数据库、网页、代码或业务系统。
3. **中间会出现反馈**：搜索可能为空、测试可能失败、权限可能不足。
4. **结果可以验收**：文件能打开、测试能运行、来源能核对、业务状态能查询。

反过来，如果只是改写一句话、翻译一小段、按固定公式算个数，普通模型调用或确定性程序更省事。

## Agent 不是一个"数字员工"承诺

把 Agent 包装成"像员工一样什么都能做"，听着直观，但遮住了三件事：

- 多步骤任务中，每一步的错误都可能影响后面；
- 外部资料可能包含恶意指令，诱导它越权；
- 付款、删除、发送和发布等动作不能只靠模型自己判断。

靠谱的教程不会只放成功 Demo。它必须讲停止条件、权限、检查点、人工确认和评测——这些在 B、C 两条路线里逐步补齐。
