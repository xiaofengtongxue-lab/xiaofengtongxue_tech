# Codex App、CLI、IDE 和云任务怎么选

选择入口时不要问“哪个最强”，而要问“这个任务在哪里最容易提供上下文、执行验证和审查结果”。本页给出一套可直接套用的判断方法，并用三个典型工作流演示如何组合使用不同入口。

## 30 秒选择法

按下面顺序判断：

1. 任务是否紧贴当前正在看的几行代码？是，优先用 IDE。
2. 是否需要终端可复现、管道输入、JSON 输出或 CI？是，优先用 CLI。
3. 是否需要同时管理多个长任务、预览文件、浏览页面或审查 Git diff？是，优先用桌面应用。
4. 是否希望任务在隔离环境中远程运行，或和本地工作并行？是，考虑云任务。

## 四种入口的真实取舍

### IDE：上下文最贴近编辑动作

适合：解释选中代码、补局部测试、修一个明确诊断、按项目样式改当前组件。

优势是当前文件、选区和编辑器诊断就在手边。缺点是大型跨模块任务容易让你只盯着局部，而忽略仓库状态、终端验证和部署边界。

推荐提示：

```text
先解释当前选中函数的输入、输出和三个边界条件。
只修改这个函数和它的测试，不改变公开 API。
修改后运行最小相关测试，并报告命令和结果。
```

### CLI：最容易复现和自动化

适合：服务器环境、远程开发、批处理、脚本、CI、日志分析，以及你希望保留完整终端记录的任务。

常用启动方式：

```bash
codex -C /path/to/project
```

一次性任务可使用：

```bash
codex exec -C /path/to/project "检查当前未提交修改，只报告 P1 和 P2 问题"
```

CLI 的优势是每个参数和命令都能记录。缺点是文件预览、视觉对比和多任务管理不如桌面应用直观。

### 桌面应用：适合复杂交付和并行管理

适合：从调查到修改再到审查的长任务、多项目切换、文档/PPT/表格生成、内置浏览器验证、Git 暂存与逐行反馈。

从终端打开当前目录：

```bash
codex app .
```

桌面应用不是“更大的聊天框”。它更像一个任务控制台：一个任务负责一个清晰目标，你可以在审查面板里检查整个仓库的 diff，而不只是代理最后一条消息。

### 云任务：适合隔离、并行和远程执行

适合：耗时重构、并行尝试、自动创建 PR、无需占用本机环境的任务。

云任务需要提前配置仓库和云环境。它的优势是与本机隔离；代价是本地未提交状态、私有依赖、网络和秘密变量必须显式处理。不要把“本机能运行”默认等同于“云环境也能运行”。

## 推荐的日常组合

大多数工程师不需要四选一，下面两种组合已经能覆盖大部分工作。

### 组合一：IDE + CLI

1. 在 IDE 中选中代码，快速讨论局部方案。
2. 把完整修改交给当前任务执行。
3. 在终端运行项目级测试、Git diff 和构建。
4. 用 `codex review --uncommitted` 做独立审查。

适合习惯一直留在编辑器中的开发者。

### 组合二：桌面应用 + CLI

1. 在桌面应用中拆分任务、查看文件和管理长任务。
2. 用集成终端或外部 CLI 运行可复制命令。
3. 在审查面板中逐文件查看差异。
4. 需要批处理时切到 `codex exec`。

适合同时处理多个仓库、文档和非代码交付的人。

## 三个任务怎样选入口

### 场景一：线上错误刚出现

先用 CLI 保存日志、复现命令和退出码；再在 App 或 IDE 中阅读相关代码。不要先把一大段未经脱敏的生产日志粘贴到任务里。

### 场景二：根据截图做新页面

用 App 或 IDE 附加截图并实现，用浏览器检查页面，再用 CLI 跑构建与测试。截图只表达静态外观，响应式、交互和错误状态仍要在文字里说明。

### 场景三：大型重构

先在本地 App/IDE 只读调查并形成分阶段计划；确认边界后，将独立里程碑交给云任务或 worktree 并行完成；最后回到本地跑完整验证。

## 不要这样选

- 因为“云端更自动”就把没有测试的仓库直接交给云任务。
- 因为“IDE 看得到代码”就忽略未提交文件和跨模块影响。
- 因为“CLI 很专业”就把需要视觉判断的任务硬写成纯命令。
- 在同一工作目录同时让多个任务修改相同文件，却没有 worktree 或文件所有权约定。

## 验证你选对了

执行一个 20 分钟内能结束的小任务，然后回答：

- 上下文是否容易提供？
- 执行中能否及时纠偏？
- 结果是否有方便检查的 diff、文件预览或命令输出？
- 失败时能否清楚知道是哪一层出问题？

如果其中两项明显不顺，换入口通常比继续堆提示词更有效。
