# 用 Codex 制作图文、短视频和内容素材

哈喽，我是小枫。你有没有这种感觉：平时刷手机，脑子里一堆选题，可真坐下来做内容，半天憋不出几张能发的图，视频更是从脚本到字幕折腾好几天。我自己就是这样过来的——之前做一期活动招募内容，光是改公众号、小红书和短视频三个版本，来回折腾了我整整两个晚上，中间还踩了几个版权和脱敏的坑。先说明白：标题里的 Codex 是本栏目统称——普通创作者用 ChatGPT Work，走技术路线的用 Codex，下面这套流程两者通用。

后来我试着用 Codex 把这件事流程化，发现效率确实上去了。倒不是 AI 有多神奇，关键是把「事实包」和「渠道结构」拆清楚之后，后面每一步都很顺。这篇文章我就按自己的实操流程来聊，从一篇活动图文到一条 60 秒短视频，争取让你看完就能直接用。

## 不会写代码也能做

先打消一个顾虑：你不需要会写代码。我自己写代码好多年了，但这一套流程里，核心的东西是整理事实、设计结构、写文案和做分镜——这些事用 ChatGPT Work 就能搞定。后面的卡片和视频，你用 Canva、剪映、CapCut 或者任何你自己顺手的工具都行。

文章里出现的 Markdown、HTML、Remotion 和批量脚本，属于「锦上添花」的可选项，不用有压力。不碰它们也完全能出成品。

一个小建议：刚开始做的时候，目标先定成「生成草稿和预览」，发布、定时、广告预算这些操作全部留给人来确认。第一次实践，选一篇图文加一条 60 秒视频就够了，别一上来就想全渠道铺开——我就犯过这个错，结果每个版本都没打磨好。

## 第一步：建立事实包

`source-pack.md`：

```md
# 主题
新品试用活动怎样报名

# 受众
第一次了解活动的老客户

# 必须事实
- 报名开放 100 个名额
- 报名页计划 7 月 18 日上线
- 最终优惠额度和客服值班时间尚未确认

# 禁止
- 不承诺一定获得名额或尚未批准的优惠
- 不展示真实客户姓名、联系方式或后台账号
- 不复制其他教程的标题、段落和比喻

# 来源
- 已批准的活动方案
- 产品事实表和客服确认记录
```

这一步看着简单，其实是我踩坑最多的地方。以前我经常写到一半发现某个数字不确定，又跑回去翻聊天记录和文档，来回打断思路特别烦。后来学乖了，先把所有硬事实锁在一个文件里，后面图文和视频都从这个文件出发，一致性天然就有保障。

事实包通过之后，再往下走。没过之前别急着写正文，不然改起来成本很高。

## 第二步：为不同渠道分别设计结构

我入坑早期干过一件蠢事：把公众号长文直接拆成几段，当小红书笔记发。数据当然很难看——每个平台用户的阅读节奏完全不一样，不能这么偷懒。

### 公众号/博客

问题 → 常见错误 → 完整步骤 → 示例 → 验证清单。

### 小红书/轮播卡片

封面承诺 → 3-6 个关键步骤 → 错误示例 → 一页清单 → 延伸阅读。

### 60 秒短视频

0-3 秒问题钩子 → 3-45 秒三个动作 → 45-55 秒验证 → 55-60 秒总结。

我的做法是先扔一个提示给 Codex，让它把三个渠道的结构都列出来，我审核一遍再往下走：

```text
基于 source-pack.md，分别设计博客、8 页轮播卡片和 60 秒视频的内容结构。三者事实一致，但不要逐句复用。先输出结构和每一部分的传播目标，不写成稿。
```

这一步的核心是确认「骨架」对了，事实没有跑偏，各渠道的节奏也合理。确认完结构再动手写正文，翻车的概率就小很多。

## 第三步：完成原创写作

结构定好了，接下来写博客正文。提示参考：

```text
写博客正文。开头直接回答读者会得到什么；活动日期、名额、规则和未确认信息保持精确；使用自己的结构和例子；每个步骤包含预期结果与失败处理。不要沿用来源的标题顺序和标志性表达。
```

正文出来后，我会跑一遍「来源脱敏」自查，这是我自己总结的几个点：

- 结构是否独立，和参考来源不一样；
- 句式和比喻有没有明显雷同；
- 有没有大段连续近似表述；
- 引用是不是必要、是不是够短；
- 事实链接有没有保留。

我之前有一篇，写完发现某个段落的结构和原文几乎一样，只是换了几个词，读者一眼就能看出来。那次之后我就把这几条固定成自己的检查习惯了。

## 第四步：生成轮播卡片

工具选择很多：Canva、Figma、社交卡片 Skill，或者用 HTML→PNG 的工作流都行。我自己习惯先用 Canva 快速出图，确认内容没问题再做精调。

提示：

```text
把已确认内容制作成 8 页 3:4 轮播卡片。

要求：
- 每页一个信息点；
- 封面不使用焦虑、夸张收益和绝对承诺；
- 日期、步骤和行动按钮清楚可读；
- 正文字号适合手机；
- 统一页码和品牌；
- 生成后拼接 contact sheet 检查节奏和重复；
- 不发布。
```

除了逐页检查，我还会把所有卡片缩略图拼在一起整体看：颜色是不是太单调、页面是不是全是同一种布局、重点够不够突出。这个「远看」的视角特别有用，有时候单张看着不错，拼一起就发现节奏有问题。

## 第五步：生成视频脚本和分镜

```text
把内容改编为 60 秒竖屏说明视频。输出 timecode、旁白、画面、屏幕文字、素材和转场。旁白使用自然口语，屏幕文字只保留关键词。涉及报名页面和客户反馈的画面必须使用脱敏演示素材。
```

拿到脚本之后，我建议你先自己读一遍旁白，拿手机计时。60 秒中文旁白不要只按字数猜——每个人的语速差不少，我正常说话大概是每分钟 220-240 字，但做视频旁白会稍微慢一点。实际录出来才知道到底超不超时，我第一次做 60 秒视频，光改旁白就改了四版。

## 第六步：制作画面与录屏

素材优先级，我自己是这么排的：

1. 自己录制的脱敏操作；
2. 自有截图和图表；
3. 经过授权的品牌资产；
4. AI 生成的说明性插图；
5. 有明确商业许可的素材库。

特别提醒一句：AI 生成的图，别拿来伪造真实产品效果、数据、用户评价或者操作结果。这个边界踩了真的很麻烦，不止是平台处罚的问题，读者信任一旦丢了就很难挽回。

## 第七步：配音、字幕和剪辑

Remotion、HeyGen 或者你熟悉的视频工具都可以用。提示：

```text
按 storyboard.csv 生成 1080x1920、30fps 预览视频。字幕使用最终旁白的真实时间码，保留底部安全区。只用已批准素材和音乐。输出预览 mp4、srt 和素材 manifest，不上传平台。
```

关于声音这块：真人录音、克隆声音和数字人都需要明确的授权，别随便用网上找到的素材。另外各平台对 AI 生成内容的标注规则不太一样，发之前看一眼当前的要求，按要求标注。

## 第八步：多尺寸变体

不同平台要不同比例，但别简单裁切了事——画面主体可能直接被切没了。

- 9:16：短视频主版；
- 1:1：信息流方图；
- 16:9：横版视频/封面；
- 3:4：轮播卡片；
- 2.35:1 或平台特定比例：公众号封面。

每个比例重新检查安全区、文字位置、人物构图。用 Canva Resize 或者模板 Skill 能省不少时间，但我还是会在每个版本里手动过一遍——自动化尺寸变换有时候文字会跑偏，不亲眼看过不放心。

## 第九步：发布前检查

发布之前我会对着这个清单逐项过一遍，亲眼确认。

### 事实

- 日期、名额、规则、数字和链接正确；
- 演示结果与真实操作一致；
- 没有夸大收益和绝对结论。

### 版权与隐私

- 素材、音乐、字体、Logo 和肖像有权使用；
- 录屏没有账号、通知、路径、Token 和用户数据；
- AI 生成内容按平台要求披露。

### 技术

- 分辨率、编码、时长、音量、字幕和封面正确；
- 手机上文字可读；
- 链接和二维码在目标渠道可用。

### 发布

- 标题、简介和标签不误导；
- 评论/客服预案就绪；
- 发布、定时和广告预算由人确认。

我踩过一个坑：视频导出完了才发现字幕里夹了一段录屏时的路径信息，差点把本地目录结构暴露出去。所以「录屏脱敏」这条我每次都重点检查。

## 第十步：把稳定流程做成 Skill

当同一套流程——事实包 → 多渠道结构 → 素材 → QA——连续跑通几次之后，就可以把它固化成自己的 Skill 了。固定好输入目录、输出命名、尺寸表和检查表，下次直接复用。

注意一个点：Skill 里写的是方法，别把某篇具体文章的内容焊死在里面。不然换个选题就又得重新做。

## 常见失败

### 同一文案复制到所有渠道

事实保持一致没问题，但结构和节奏得按渠道重新来过。偷懒复制粘贴，数据一定不好看。

### 卡片文字太多

每页只放一个结论，长解释用链接指回正文。读者在手机上滑卡片，没人愿意读大段文字。

### 视频配音和字幕不同步

先锁最终音频，再对着音频打时间码生成字幕。别先写字幕再去对齐音频——倒过来做效率低还容易出错。

### 自动发布未经检查

默认只生成草稿和预览，要不要发布到外部平台，一定一定由人来拍板。这个原则我从来没破过。

## 完成门槛

- [ ] 事实包和来源已确认。
- [ ] 各渠道结构独立，不机械复制。
- [ ] 图文和视频都经过真实渲染检查。
- [ ] 素材、字体、音乐和肖像有授权。
- [ ] 录屏和文件已脱敏。
- [ ] 发布、投放和预算由人批准。
