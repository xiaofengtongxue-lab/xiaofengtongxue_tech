# 用 Codex 搭建电商运营工作流

Codex 在电商中的价值不是“自动写一段商品文案”，而是把产品事实、研究、定价、素材、页面、上架和复盘串成可追溯的数据流。本页以一个虚构的保温杯新品为例，演示小团队怎样跑通闭环。

## 普通运营人员怎样完成本章

你可以用 ChatGPT Work、Excel、图片能力和店铺后台的草稿功能完成主流程，不需要开发 Shopify 或编写脚本。把产品事实放在 Excel、Word 或表格中，生成的 Listing、详情页结构、客服话术和运营表先作为草稿，由人手工复制、上传和上架。

文中的 Markdown 文件可以换成普通文档；Shopify 开发、自建站代码、自动数据清洗和接口连接都属于技术增强选项。第一次实践不要连接真实店铺，使用虚构产品或测试账号。

不熟悉文件、权限和人工审批时，先学习 [普通人项目与文件管理](/codex/everyday/projects-files) 和 [隐私、权限与审批](/codex/everyday/safety)。

## 先定义哪些事情不能交给模型决定

必须由人或权威来源确认：

- 产品规格、材质、认证和安全声明；
- 成本、税、物流、库存和售后政策；
- 商标、图片、模特和音乐授权；
- 平台规则和广告合规；
- 最终价格、促销、上架、投放和退款；
- 用户评价真实性。

Codex 可以整理、计算、生成草稿和执行受控工具，但不能编造检测结论、销量、用户评价或竞品数据。

## 第一步：建立产品事实表

`product-facts.md`：

```md
# 产品事实

- 临时名称：TrailCup 500
- 容量：500 ml
- 材质：304 不锈钢内胆
- 重量：310 g（样品实测，误差待确认）
- 保温时长：尚无正式检测，不对外宣称
- 颜色：黑、白、绿
- 包装：杯体、杯盖、说明书
- 售后：30 天未使用退货，具体按销售地区规则确认
- 禁止表达：医疗功效、绝对防漏、行业第一、虚构认证
```

所有后续文案和图片都以此为单一事实源。未知字段写“待确认”，不要留给模型补齐。

## 第二步：做有来源的市场研究

可使用 Web Search、Particl Market Research、Semrush、Similarweb 或平台公开数据，具体取决于可用 Plugin 和授权。

```text
研究 500ml 通勤保温杯市场，目标是了解消费者场景、常见价位、卖点表达和差评原因。

要求：
- 使用最近 12 个月可访问来源；
- 每条数据给出链接和日期；
- 区分平台公开事实、商家自述和你的分析；
- 不绕过登录、验证码、robots 或平台限制；
- 不复制竞品文案和图片；
- 输出 research.md 和 claim-ledger.csv。
```

`claim-ledger.csv` 建议字段：`claim`、`source`、`date`、`type`、`confidence`、`allowed_use`。

## 第三步：把研究转成定位，而不是拼关键词

让 Codex生成选择矩阵：

```text
基于 product-facts.md 和 research.md，提出 3 个定位方向。
每个方向包含目标人群、使用场景、核心价值、支持证据、不能说的内容、建议价位和主要风险。
不要使用没有产品事实支持的卖点。
```

由人选择一个方向，例如“通勤轻量、易清洁”，再冻结为 `positioning.md`。

## 第四步：建立 SKU、成本和利润模型

用 Spreadsheets 能力创建 `unit-economics.xlsx`，至少包含：

- SKU、颜色、采购成本；
- 包装、头程、末端配送；
- 平台费、支付费、税费；
- 售后和损耗假设；
- 售价、折扣和毛利；
- 广告成本情景；
- 盈亏平衡 ROAS 或获客成本。

提示：

```text
根据 costs.csv 建立可编辑利润模型。所有假设放在单独 Assumptions 工作表并标明来源/负责人。公式不要写死数字。创建 Base、Optimistic、Conservative 三种情景，并高亮毛利为负的 SKU。
```

人工复核公式和税费口径，不能把生成表格直接当财务结论。

## 第五步：生成 Listing 草稿

```text
基于 product-facts.md 和 positioning.md，生成英文 Amazon 风格 Listing 草稿：标题、5 条 bullet、产品描述、搜索词候选和 FAQ。

要求：
- 所有规格与事实表一致；
- 不使用最高级、虚构认证、销量和用户评价；
- 不复制竞品句子；
- 每条卖点标注对应事实字段；
- 输出一份逐条合规自查。
```

不同平台对标题长度、敏感词和图片有自己的规则，发布前用当前平台官方要求复核。

## 第六步：先做详情页信息脚本

不要直接生成十张图。先输出：

| 模块 | 用户问题 | 核心信息 | 证据 | 视觉建议 |
| --- | --- | --- | --- | --- |
| 首屏 | 这是什么，适合谁 | 通勤轻量保温杯 | 容量、重量 | 产品主图 + 场景 |
| 细节 | 是否容易清洗 | 杯口/结构 | 实物照片 | 结构特写 |
| 规格 | 是否适配杯架 | 尺寸待确认 | 测量数据 | 尺寸图 |

未确认尺寸不得先生成精确尺寸图。

## 第七步：生成有授权的商品素材

输入真实产品照片或经过授权的 3D/设计图，使用图像生成或 Canva/Figma 做背景、构图和信息图。提示要锁定不能改变的产品特征：

```text
以附件真实杯体为主体，生成一张 4:5 通勤场景主视觉。保持杯盖结构、Logo 位置、颜色和比例不变；只更换背景和光线。不要增加不存在的配件、认证或文字。输出前检查产品结构是否漂移。
```

AI 图必须逐张检查：结构、颜色、文字、手指/人物、反射、尺寸暗示和版权。必要时标记为示意图。

## 第八步：搭建页面或店铺草稿

开发 Shopify 时，可使用官方 Shopify Plugin 提供当前 GraphQL、Liquid、Hydrogen 和 CLI 指导；自建站可使用 Build Web Apps、Figma、Stripe、Supabase 等能力。

```text
在现有 Shopify theme 中新增产品详情模板草稿，复用现有 section 和设计 token。内容来自 approved-listing.md，图片来自 approved-assets/。先在本地预览，不连接生产主题、不发布。

验收：移动端首屏、变体选择、库存状态、配送/退货说明、错误状态和结构化数据均可检查。
```

先生成 preview URL 或本地页面，由人核对后再决定是否同步到店铺。

## 第九步：客服和运营只生成草稿

根据真实政策建立 FAQ 和回复模板：

```text
把 support-policy.md 转成 10 个高频客服回复草稿。保持退款、保修和配送规则原文，不承诺额外补偿。遇到人身安全、法律威胁、支付争议和异常退款时升级人工。
```

连接邮箱、工单或店铺后，默认只读取和起草，不自动发送、退款、关单或改订单。

## 第十步：建立复盘数据流

周期性导出或连接：流量、转化、广告、退款、库存和客服原因。让 Codex生成可复现分析：

```text
分析 weekly/*.csv，统一 SKU 和日期口径。输出：销售漏斗、毛利、广告情景、退款原因和库存风险。所有图表可追溯到清洗脚本和源文件。不要把相关性写成因果。
```

稳定后再固化为 Skill 或定时任务。

## 常见失败

### 先写营销文案，后补产品事实

顺序反了。事实表必须是单一来源。

### 把竞品页面改写后当原创

研究用于理解市场，不复制结构、文案、图片和商标。

### AI 图改变真实商品

锁定结构并逐张 QA；核心规格图优先使用真实拍摄或经过确认的设计资产。

### 自动上架和投流

发布、价格、预算和付款必须保留人工审批。

## 完成门槛

- [ ] 产品事实、未知项和禁用表达清楚。
- [ ] 市场结论有来源和日期。
- [ ] 利润模型公式与假设人工复核。
- [ ] Listing 每条主张能回到事实字段。
- [ ] 素材版权和产品一致性通过检查。
- [ ] 店铺只在预览/草稿环境验证。
- [ ] 上架、投放和客服写操作由人批准。
