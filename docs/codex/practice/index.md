# Codex 技巧与场景实战

这个栏目讨论的不是“神奇提示词”，而是怎样把一个真实工作拆成输入、生产步骤、中间产物、工具调用、质量检查和人工审批。Codex 可以编排很多工具，但不会自动替你补齐事实、版权、商业判断和发布责任。

## 先建立一个通用生产模型

无论做 PPT、商品页还是漫剧，都按六步走：

1. **定义交付物**：文件类型、受众、尺寸、渠道和完成标准。
2. **整理可信输入**：事实、数据、素材、品牌规范和禁止事项。
3. **先产结构**：大纲、信息架构、分镜或数据分析计划。
4. **分批生成**：每一批都有可检查的中间产物。
5. **渲染与验证**：打开真实文件/页面/视频检查，不只读文本报告。
6. **人工批准外部动作**：发送、分享、上架、投放、发布和付款。

如果没有第 5 步，Codex 生成的“文件”可能语法正确但视觉不可用；如果没有第 6 步，自动化可能把草稿变成公开事故。

## 选择 Skill 和 Plugin 的原则

先检查当前环境：

```bash
codex plugin list --available --json
```

在任务中通过 `/skills` 或 `$` 查看 Skill。不同版本、套餐和工作区可能提供不同能力。

选择顺序：

1. 优先使用当前 Codex 内置并有完整验证流程的文件类能力；
2. 需要实时外部系统时使用官方/可信 Plugin 或 MCP；
3. 社区 Skill 安装前审查源码、脚本、网络、权限和许可证；
4. 工作流稳定后再创建自己的 Skill；
5. 不为“一句话生成”牺牲可编辑性、来源和质量检查。

## 通用任务开场模板

```text
我要完成 [交付物]，用于 [受众/渠道]。

输入：
- [文件、数据、链接和素材]
- 其中 [来源] 是事实依据，[来源] 只作为风格参考

交付：
- 文件类型：[pptx/xlsx/pdf/mp4/site/...]
- 尺寸/时长：[要求]
- 必须包含：[内容]

边界：
- 不编造数字、引用、评价或产品能力
- 不使用无授权素材、商标、人物肖像或音乐
- 不发送、分享、上架、投放或发布

先给出生产计划和中间检查点。每完成一个阶段，提供可查看的产物和验证结果。
```

## 质量检查的四个层次

1. **事实**：数据、名称、时间、规格和来源正确。
2. **结构**：故事线、信息层级和用户流程清楚。
3. **文件**：格式可打开、元素可编辑、公式/链接/字幕有效。
4. **发布**：版权、隐私、品牌、平台规则和人工审批通过。
