# 用 Codex 制作可交付的 PPT

高质量 PPT 不是“一句话生成 20 页”，而是先把结论、证据和受众决策整理清楚，再选择可编辑 PPTX、图片型幻灯片或在线 Slides 路线。本页以一份 10 页项目复盘汇报为例，跑通从资料到交付文件的完整流程。

## 不会写代码怎样完成本章

普通用户优先选择 ChatGPT Work：附加 Word、Excel、PDF、图片和品牌模板，选择当前可用的演示文稿能力，先确认页级故事线，再生成可编辑 `.pptx`，最后用预览批注和 PowerPoint 完成复查。全程不需要终端。

下文出现的目录结构可以直接用 Finder 或文件资源管理器创建；`.md` 只是文本文件示例，也可以换成 Word 或普通文本。HTML、脚本和程序化检查属于技术增强选项，可以跳过。

如果你还不会管理附件和检查文件，先完成 [普通人第一次文件任务](/codex/everyday/first-result) 和 [文件验收教程](/codex/everyday/review-revise)。

## 第一步：选择正确技术路线

| 路线 | 优点 | 代价 | 适合 |
| --- | --- | --- | --- |
| 原生可编辑 PPTX | 文字、图表和形状可继续编辑 | 视觉需要更多排版 QA | 商务汇报、长期维护 |
| 图片型 PPTX | 视觉统一、生成快 | 单页难编辑，文字和数据修改成本高 | 概念提案、视觉展示 |
| Google Slides/Canva | 协作和模板生态好 | 需要账号、插件和外部权限 | 团队在线协作 |
| HTML/网页演示 | 动画和交互自由 | 不是标准办公文件 | 技术演示、线上发布 |

如果交付方明确要求 `.pptx` 且后续要改数字，优先原生可编辑路线。

## 第二步：整理证据包

准备一个干净目录：

```text
project-review/
├── brief.md
├── metrics.xlsx
├── timeline.md
├── screenshots/
├── brand/
└── output/
```

`brief.md` 至少写：

```md
# 汇报目标

- 受众：产品负责人和技术负责人
- 时长：12 分钟
- 目的：决定下季度是否继续投入
- 核心结论：试点有效，但转化和交付成本仍需优化
- 页数：8-10 页
- 禁止：不得编造用户反馈、ROI 或未来承诺
```

数字必须能追溯到表格单元格或正式来源。截图标明日期、环境和是否可公开。

## 第三步：先做页级故事线

不要先生成文件。发送：

```text
使用 brief.md、metrics.xlsx 和 timeline.md，为 12 分钟项目复盘设计 9 页故事线。

要求：
- 每页只有一个结论句；
- 结论先于背景；
- 每个数字标注来源文件/工作表；
- 区分事实、分析和建议；
- 最后一页必须给出需要决策的三个选项；
- 先只输出页码、页标题、核心证据、建议视觉和讲述目的，不生成 PPT。
```

合格故事线示例：

```text
1. 标题：试点证明需求存在，但尚未证明规模化效率
   证据：试点周期、样本量、核心结论
   视觉：一条结论 + 三个事实数字
```

如果页标题只是“项目背景”“数据分析”，继续改成有结论的完整句子。

## 第四步：确定视觉系统

提供品牌资产或明确规范：

```text
视觉方向：克制的技术商务风。
- 16:9
- 深蓝黑文字，浅灰背景，蓝色只用于重点
- 标题 28-32pt，正文不小于 16pt
- 每页最多一个主要图表
- 不使用装饰性 3D、无意义渐变和密集卡片
- 所有图表保留数据标签和来源脚注
```

没有品牌字体时使用跨平台常见字体，避免在交付电脑上替换后错位。

## 第五步：选择并调用文件能力

先查看当前可用项：

```bash
codex plugin list --available --json
```

常见选择：

- Codex 环境中的 Presentations 文件能力；
- Google Drive/Slides Plugin；
- Canva Plugin；
- 经过审查的社区 PPT Skill；
- 自己基于 PptxGenJS 等工具编写的仓库级 Skill。

在任务中显式指定当前列表里的 Skill/Plugin 名称：

```text
使用可用的 presentations 能力，按已确认的 9 页故事线生成可编辑 .pptx。

要求：
- 文字、基础图表和形状保持可编辑；
- 数据只来自 metrics.xlsx；
- 在备注中写每页讲述要点和来源；
- 输出到 output/project-review.pptx；
- 生成后渲染每一页为图片进行视觉检查。
```

如果当前没有相关能力，先安装可信 Plugin/Skill，或让 Codex在项目内使用成熟 PPTX 库生成，但仍必须执行渲染验证。

## 第六步：渲染，而不是只检查文件存在

合格流程应把 `.pptx` 渲染为 PDF 或逐页 PNG，再检查：

- 字体是否替换；
- 文本是否溢出或被裁切；
- 图表标签是否重叠；
- 图片是否模糊、变形或带水印；
- 对齐、边距和页码是否一致；
- 颜色对比是否可读；
- 页面之间是否过于重复；
- 16:9 尺寸是否正确。

提示：

```text
渲染全部页面并逐页检查。先输出问题清单，按“阻止交付 / 影响理解 / 视觉细节”分级。修复后重新渲染受影响页面，直到没有文字溢出、遮挡和数据错误。
```

## 第七步：做内容一致性检查

```text
对照源文件检查 PPT：
1. 每个数字、日期、名称和百分比；
2. 图表与正文是否使用同一口径；
3. 事实、分析、建议是否混淆；
4. 首页结论与最后决策是否一致；
5. 备注与页面内容是否矛盾。

输出逐页核验表。不要根据常识补数字。
```

## 第八步：检查可编辑性

在 PowerPoint 或兼容软件中打开，随机检查：

- 标题和正文能否单独编辑；
- 图表是可编辑图表还是一张图片；
- 图片是否被错误拉伸；
- 母版、主题色和字体是否可统一修改；
- 备注和超链接是否保留；
- 导出 PDF 后页面无变化。

图片型路线则应明确交付限制，不要宣称“完全可编辑”。

## 一份高质量生成提示

```text
制作一份 9 页、16:9 的项目复盘 PPTX，受众是产品和技术负责人，汇报时间 12 分钟。

使用已确认的页级故事线。数据只来自 metrics.xlsx；截图只来自 screenshots/。每页标题必须是结论句，正文最多 3 个要点。图表保留来源脚注，备注写讲述要点。

保持文字、图表和形状可编辑。不要使用未授权图片、品牌 Logo 或虚构用户评价。生成后渲染全部页面，完成文字溢出、对齐、数据和可编辑性检查。不要上传、分享或发送文件。
```

## 常见失败

### “一键生成”内容空泛

先确认故事线和证据包，再生成文件。

### 每页都是卡片和装饰图

要求每页一个结论，并按证据选择表格、图表、流程或大数字，不强制统一布局。

### 中文字体错位

使用交付环境可用字体，渲染后检查，必要时嵌入或替换。

### 图片很漂亮但数字不可改

在开始前选择原生可编辑路线；图片型 Skill 适合作为视觉草案或特定展示。

## 交付清单

- [ ] `.pptx` 可打开且比例正确。
- [ ] 页数、时长和受众匹配。
- [ ] 数字可追溯，无编造。
- [ ] 全部页面已渲染检查。
- [ ] 随机页面元素可编辑。
- [ ] 备注、来源和版权信息完整。
- [ ] 未经授权没有分享或发送。
