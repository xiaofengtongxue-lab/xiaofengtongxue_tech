# 不会编程也能用：ChatGPT Work 与 Codex 入门

这条路线写给不以编程为工作的人。你可以是运营、产品经理、教师、电商从业者、内容创作者、研究人员、行政或团队负责人。学习目标不是看懂代码，而是用自然语言和自己的资料，完成一份能够预览、修改、导出和交付的真实成果。

你不需要先学终端、Git、Markdown、Python，也不需要背一套“万能提示词”。第一阶段只使用 ChatGPT 桌面应用、附件和文件预览。

## 先分清 Chat、Work 和 Codex

当前 ChatGPT 桌面应用把不同工作放在不同入口：

| 入口 | 适合做什么 | 普通例子 |
| --- | --- | --- |
| Chat | 快速问答、解释、头脑风暴和短草稿 | 改写一封邮件、解释一个概念、比较两个方案 |
| Work | 有明确成品、需要多步处理或多个资料的工作 | 制作 PPT、分析表格、完成报告、建立项目计划 |
| Codex | 软件开发、技术任务，或确实需要操作代码和开发工具的工作 | 修改网站、调试程序、运行测试、审查代码 |

如果你以前已经用 Codex 做非编程工作，可以继续使用；但对大多数办公、研究和内容任务，Work 的界面和流程更贴近日常工作。本站仍把这条路线放在 Codex 大栏目下，是为了把文件能力、Skills、Plugins、权限和自动化串成一套完整方法，而不是把所有事情都错误地称为编程。

## 30 分钟的首次成功

完成 [第一次使用 ChatGPT Work](/codex/everyday/first-result) 后，你应该能做到：

1. 选择一份不含敏感信息的工作资料；
2. 新建一个任务并附加资料；
3. 用自己的话说明成品、受众和限制；
4. 打开生成文件的预览；
5. 指出一处具体问题并让它只修改那一处；
6. 下载文件，用 Word、PowerPoint 或 Excel 再打开检查；
7. 在发送、发布或覆盖原文件前停下来人工确认。

这就是普通用户的“第一个完整闭环”。是否写了代码并不重要，能否检查成品才重要。

## 六个常见词，用普通话理解

| 词语 | 可以怎样理解 |
| --- | --- |
| 项目 Project | 一个长期资料柜，保存同一主题的文件、任务和上下文 |
| 任务 Task | 一次只交付一个明确结果的工作单 |
| 附件 | 只为当前任务提供的文件、图片或数据 |
| 本地项目 | 让桌面应用在你授权的电脑文件夹中读取或修改文件 |
| Skill | 一套可复用的工作步骤、模板和检查标准 |
| Plugin | 可以安装的能力包，可能连接云盘、邮件、Slack 等外部服务 |

这些名词不是考试内容。遇到时知道它会接触哪些资料、会产生什么结果、是否会对外执行操作就够了。

## 普通用户最重要的三个边界

1. **先用副本**：不要第一次就把整个桌面、全部文档或唯一原文件交给任务。
2. **先出草稿**：邮件、商品、社交媒体、付款和系统修改都先生成草稿，不自动发送或发布。
3. **先看成品**：文字流畅不代表数字正确。每个名字、日期、金额、引用、公式和对外承诺都要核对。

## 学完的判断标准

- [ ] 不靠终端也能开始和完成任务。
- [ ] 知道什么时候用 Chat、Work 或 Codex。
- [ ] 会提供必要资料，而不是把所有文件全部上传。
- [ ] 会要求成品格式、人工审核点和完成标准。
- [ ] 能通过预览和批注做局部修改。
- [ ] 看得懂权限请求，遇到不明白的动作会拒绝。
- [ ] 能把稳定流程保存成模板或 Skill。
