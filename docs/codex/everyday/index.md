# 不会编程也能用：ChatGPT Work 与 Codex 入门

嘿，先别急着关掉这个页面——我知道，一看到「Codex」这个字眼，你脑子里可能马上蹦出写代码、命令行、黑底白字的终端窗口。但这次真不用。

我是小枫，说句实话，我也不是天天闷头写代码的人。更多时候我就是想用 ChatGPT 帮我搞定一份汇报 PPT、处理一堆表格数据、或者整理一份像样的研究报告。这条路线就是我自己磕磕绊绊用了几个月之后总结出来的：**用你平时说话的方式，让 AI 帮你做出真正能交付的成果**。

不管你做什么——运营、产品、教师、电商、内容、研究、行政——只要你能打字聊天，你就能走完这条路。不需要提前学终端，不需要背什么「万能提示词模板」。第一阶段只需要两样东西：ChatGPT 桌面应用，和你手头真实的工作文件。

好，咱们开始。

## Chat、Work、Codex，到底该点哪个

刚用 ChatGPT 桌面版那阵子，我自己也懵过：三个入口摆在那里，到底点哪个才对？踩了几次坑之后，我给自己总结了一个特别简单的判断方法：

| 入口 | 适合做什么 | 普通例子 |
| --- | --- | --- |
| Chat | 快速问答、解释、头脑风暴和短草稿 | 改写一封邮件、解释一个概念、比较两个方案 |
| Work | 有明确成品、需要多步处理或多个资料的工作 | 制作 PPT、分析表格、完成报告、建立项目计划 |
| Codex | 软件开发、技术任务，或确实需要操作代码和开发工具的工作 | 修改网站、调试程序、运行测试、审查代码 |

一句话记住：聊天问事用 Chat，要做文件用 Work，写代码才用 Codex。如果你之前一直在 Codex 里做非编程的活儿，继续用完全没问题；但如果你刚开始接触，Work 的界面和操作逻辑会更贴近你日常办公的感觉。

## 30 分钟，拿到你的第一个成果

先别看完整路线，咱们先定一个小目标。完成 [第一次使用 ChatGPT Work](/codex/everyday/first-result) 之后，你应该能独立做到这几件事：

1. 挑一份不含敏感信息的工作资料；
2. 新建一个任务，把资料传上去；
3. 用自己的大白话说清楚：你要什么成品、给谁看、有什么限制；
4. 打开生成出来的文件预览；
5. 指出一处具体问题，让它只改那一处，别动其他地方；
6. 下载文件，用 Word、PowerPoint 或 Excel 打开再检查一遍；
7. 在点发送、发布、或者覆盖原文件之前，停下来，人工确认一下。

这就是普通用户的「第一个完整闭环」。有没有写代码不重要，重要的是你能不能看得懂成品、敢不敢交付出去。

## 六个常见的词，用大白话说清楚

刚接触这些概念的时候我自己也头晕，后来发现它们其实没那么玄乎：

| 词语 | 可以怎样理解 |
| --- | --- |
| 项目 Project | 一个长期资料柜，保存同一主题的文件、任务和上下文 |
| 任务 Task | 一次只交付一个明确结果的工作单 |
| 附件 | 只为当前任务提供的文件、图片或数据 |
| 本地项目 | 让桌面应用在你授权的电脑文件夹中读取或修改文件 |
| Skill | 一套可复用的工作步骤、模板和检查标准 |
| Plugin | 可以安装的能力包，可能连接云盘、邮件、Slack 等外部服务 |

这些词不用背。遇到的时候，能搞清楚它会碰哪些资料、会产出什么东西、会不会对外执行操作，这就够了。

## 我自己踩过的三个坑，也是最重要的三条边界

用了一年多，我最想跟你说的其实就是三句话，每句都是交了学费换来的：

1. **先用副本试**：别第一次就把整个桌面、全部文档、或者唯一的那份原文件交给任务。一个「整理文件夹」的任务就可能把精心搭好的目录结构全改掉，万幸有备份才能恢复。
2. **先出草稿，别自动发**：邮件、商品上架、社交媒体帖子、付款操作、系统配置修改——统统先生成草稿。确认没问题了再手动发送或发布。别图省事把「发送」权限直接给出去。
3. **先看成品，别看热闹**：文字读起来流畅，不等于数字是对的。每个名字、日期、金额、引用来源、公式、对外承诺，都要亲自核对一遍。AI 写出来的东西读着太顺了，顺到容易让人放下戒备心。

## 学到什么程度算过关

- [ ] 不用终端也能开始和完成任务。
- [ ] 知道什么时候用 Chat、Work 或 Codex。
- [ ] 会提供必要的资料，而不是一股脑把所有文件全传上去。
- [ ] 会明确提出：成品格式、人工审核点、完成标准。
- [ ] 能通过预览和批注做局部修改，不是每次都推翻重来。
- [ ] 看得懂权限请求，遇到不明白的动作会点拒绝。
- [ ] 能把稳定的流程保存成模板或 Skill。
