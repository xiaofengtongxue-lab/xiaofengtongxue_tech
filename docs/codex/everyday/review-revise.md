# 怎样检查 AI 生成的 Word、PPT、表格和 PDF

嘿，你拿到 AI 生成的那份文件了——Word 排版工整，PPT 配色舒服，表格公式看着也对。这时候最容易犯的毛病就是：扫一眼觉得挺好，直接发出去。

说实话，我自己就翻过车。有一次让 Codex 帮生成一份项目复盘 PPT，排版漂亮得不行，结果发给同事后发现第三页的金额多了一个零。从那以后我就养成了习惯：**文件只是第一版，后面还有一半工作在你自己手上。**

AI 真正帮我们省下来的，是把草稿、排版、公式这些苦力活做了。但判断一个文件"能不能用"，这件事没法外包。下面这套流程就是我反复踩坑之后总结出来的，按顺序走一遍，十分钟内能避掉 90% 的雷。

## 先分四层检查

别一上来就纠结字体和颜色，按这个顺序来效率高得多：

1. **事实层**：名字、日期、金额、数据、引用和承诺都对不对；
2. **完整层**：该有的章节、页面、表格、字段都齐了吗；
3. **表达层**：结构、标题、图表、语言和视觉是不是在帮读者理解；
4. **交付层**：文件能不能打开、编辑、打印、分享，有没有藏着不该有的信息。

事实层没过的情况下，先别急着润色——把错的数字排得再好看也没用。

## 第一步：让任务先解释它做了什么

文件到手后，别急着打开，先发这样一段话：

```text
先不要继续修改。请告诉我：
1. 生成了哪些文件，分别保存在哪里；
2. 每个文件使用了哪些来源；
3. 做过哪些检查；
4. 哪些内容无法确认或没有完成；
5. 哪些地方必须由我人工审核。
```

这份说明本身不是"证据"，它的作用是帮你排一个检查优先级：哪些地方它自己都心虚，你就重点看哪些。当然，最后还是要打开文件亲自核对。

## 第二步：对照原始资料检查事实

下面这些内容出了问题，是真的可能造成实际损失的，优先盯：

- 人名、公司名、产品名；
- 日期、截止时间和时区；
- 金额、税费、折扣、单位和小数位；
- 合同、政策、认证和监管表述；
- 直接引语和来源链接；
- 对外承诺、退款、保修和服务范围；
- 图表中的口径、时间范围和样本数量。

我常用一个小技巧——让它自己生成一份对照表：

```text
请把最终文件中的所有数字、日期和对外承诺列成表格，逐项标明来源文件和原文位置。没有来源的内容标红并说明，不要自动修改。
```

拿到这个表之后，你只需要**抽查**几条来源就行。别因为表格列得详细就觉得引用肯定真实存在——我见过它把年份凭空捏造的情况，表格做得再漂亮也没用。

## 第三步：检查有没有漏掉必须内容

最省力的办法是在任务一开始就列好清单。比如一份项目复盘，至少得包含这些：

- 目标与时间范围；
- 核心结果；
- 计划与实际差异；
- 原因和证据；
- 风险；
- 下一步、负责人和日期；
- 需要管理层决定的事项。

然后让它自己对着清单找：

```text
根据我最初的要求建立验收清单，逐项标明最终文件中的页码、章节或工作表位置。找不到的项目写"缺失"，不要用相近内容代替。
```

注意那个"不要用相近内容代替"——你不强调的话，它可能拿一个似是而非的段落凑数。

## 第四步：使用预览和批注做局部修改

桌面应用都能预览文档、演示文稿、表格和 PDF。看到有问题的地方，指向具体位置说清楚：

```text
这张图的标题没有说明时间范围。只把标题改成"2026 年第二季度各渠道新增客户"，数据和图表类型保持不变。
```

```text
这一段把建议写成了已经决定的事实。改成"建议方案"，保留后面的证据，不改其他章节。
```

```text
这个表格在页面中放不下。优先缩短列名和调整列宽，不删除金额、单位和来源列。
```

批注式修改的好处是：已经确认没问题的地方不会被动到。只有整个结构都歪了的时候，才考虑重新生成。

## Word 和普通文档怎样检查

- 标题层级是不是连续的，目录点下去能不能跳转；
- 页眉、页脚、页码和日期对不对；
- 表格跨页的时候有没有断裂或者文字被截掉；
- 引用、脚注和链接能不能定位到来源；
- 字体、行距和段落间距是不是统一；
- 文档还能不能编辑（小心它给你整成一整页图片）；
- 修订痕迹、批注和隐藏内容适不适合对外交付。

下载后，用 Word、Pages 或者接收方实际用的软件重新打开。预览看着正常，换个软件排版就可能面目全非——这是真实发生过的。

## PPT 怎样检查

先看故事线，再看好不好看：

1. 每一页能不能用一句话说出结论；
2. 页面顺序是不是在帮听众做决定；
3. 同一个数字在标题、图表和备注里是不是一致的；
4. 图表的坐标、单位、图例和时间范围够不够清楚；
5. 字号投到投影或者会议室屏幕上还能不能看清楚；
6. 图片、Logo、字体和模板有没有版权问题；
7. 每个文本框、图表和形状还能不能继续编辑；
8. 演讲备注和来源完不完整。

还有一个特别管用的办法：把所有页面缩略图排在一起扫一眼，重复版式、太密的页面、突然画风突变的，一眼就能看出来。然后随机挑三页改一下文字——如果改不动，说明它给你的是整页图片，不是真正的 PPT。

## Excel 和表格怎样检查

- 列名、单位、日期格式和数据范围是不是一致的；
- 原始数据、计算过程、假设和结果分开了没有；
- 公式引用的是单元格还是直接把数字写死了；
- 筛选、排序和合并单元格有没有把数据搞乱；
- 空值、重复值和异常值是怎么处理的；
- 总计和分项能不能对上；
- 图表引用范围对不对；
- 改一个输入值之后，相关结果跟着变了没有。

我自己会做一个快速验证：复制一份文件，在"假设"那页改一个你确定知道结果的输入值，看输出和图表有没有跟着走。测试完删掉副本，别污染正式文件。

## PDF 怎样检查

- 每一页是不是完完整整渲染出来了，没有空白、重叠或者被裁掉；
- 中文字体显示正常吗；
- 目录、书签和链接还有效吗；
- 页面尺寸、方向和打印效果是不是你想要的；
- 文字还能不能搜索（有些 PDF 里面文字被转成了模糊图片）；
- 扫描件提取的时候有没有漏掉表格、脚注和印章附近的文字；
- 敏感字段是真的被移除了，还是只是用黑色方块盖住了。

说到敏感信息，特别提醒一下：如果涉及正式脱敏，请用靠谱的 PDF 脱敏功能，脱完后再提取一次文字验证。光在视觉上遮住是不够的——黑色方块下面可能还躺着原始内容。

## 第五步：让它做反向检查

局部修改都做完之后，发这一段：

```text
请把最终文件与原始资料和最初要求做一次反向检查。

输出四部分：
1. 已满足的要求及所在位置；
2. 仍缺失或无法确认的内容；
3. 最终文件中没有来源支持的陈述；
4. 需要我在发送前人工确认的风险。

只输出检查报告，不再修改文件。
```

反向检查的价值在于：它可能会说出一些之前漏掉的东西。但别把它当最终裁定——哪些风险可以接受、哪些必须改，这个决定还是你来做。

## 第六步：在真实交付环境中打开

发出去之前，至少做一次真实环境检查：

- Word 文件用团队常用的 Word 版本打开；
- PPT 在实际投影比例和演示模式中播放；
- Excel 在接收方使用的软件中重算公式；
- PDF 在浏览器和常用阅读器各打开一次；
- 需要打印的文件实际打印或导出打印预览；
- 需要上传平台的文件先在草稿环境测试尺寸、大小和格式。

听上去啰嗦，但每一条背后都有翻车故事。尤其是 PDF 在浏览器和阅读器里各开一次——这两个引擎渲染出来的效果真的可能不一样。

## 常见失败

### 只看首页或第一页

错误经常藏在后面的表格、备注、公式和附录里。文档逐章、PPT 逐页、表格逐工作表检查，不要省这一步。

### 文件很漂亮，就忽略数字错误

先核事实再评视觉。金额、日期、单位和来源一旦出错，整个成品的价值就没了，排版再好看也救不回来。

### 让它"整体再优化一次"

大范围重写会把之前你已经确认过的内容也一起动掉。用批注做局部修改，并且说清楚哪些事实和页面是锁死的、不能碰。

### 只确认文件存在

文件生成了，跟你"能打开、能编辑、能打印"之间还有距离。必须在真实软件和真实使用场景里复查。

## 通用交付清单

- [ ] 所有重要数字、日期、名字和承诺已对照来源。
- [ ] 必需章节、页面、字段和工作表齐全。
- [ ] 没有把建议、推断写成已确认事实。
- [ ] 生成文件已逐页或逐表预览。
- [ ] 至少完成一次局部批注修改。
- [ ] 文件在真实交付软件中正常打开并可编辑。
- [ ] 没有隐藏敏感信息、批注或错误链接。
- [ ] 发送、发布、打印或上传仍由人工执行。
