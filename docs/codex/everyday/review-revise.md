# 怎样检查 AI 生成的 Word、PPT、表格和 PDF

生成文件只是第一版，不是任务结束。普通用户真正需要掌握的核心能力不是写代码，而是判断一个看起来完整的文件是否事实正确、结构清楚、能够继续编辑，并且适合真实交付。

## 先分四层检查

按固定顺序检查，避免一开始只纠结颜色和字体：

1. **事实层**：名字、日期、金额、数据、引用和承诺是否正确；
2. **完整层**：必须出现的章节、页面、表格、字段是否齐全；
3. **表达层**：结构、标题、图表、语言和视觉是否帮助读者理解；
4. **交付层**：文件能否打开、编辑、打印、分享，是否包含敏感信息。

如果事实层没过，先不要花时间润色。

## 第一步：让任务先解释它做了什么

文件生成后发送：

```text
先不要继续修改。请告诉我：
1. 生成了哪些文件，分别保存在哪里；
2. 每个文件使用了哪些来源；
3. 做过哪些检查；
4. 哪些内容无法确认或没有完成；
5. 哪些地方必须由我人工审核。
```

这份说明不是证明，只是帮助你确定检查顺序。仍要打开文件核对。

## 第二步：对照原始资料检查事实

优先检查最可能造成真实损失的内容：

- 人名、公司名、产品名；
- 日期、截止时间和时区；
- 金额、税费、折扣、单位和小数位；
- 合同、政策、认证和监管表述；
- 直接引语和来源链接；
- 对外承诺、退款、保修和服务范围；
- 图表中的口径、时间范围和样本数量。

可以要求它生成一份对照表：

```text
请把最终文件中的所有数字、日期和对外承诺列成表格，逐项标明来源文件和原文位置。没有来源的内容标红并说明，不要自动修改。
```

然后自己抽查来源。不要因为表格看起来详细就默认引用真实存在。

## 第三步：检查有没有漏掉必须内容

在任务开始前就列清单最有效。例如一份项目复盘至少需要：

- 目标与时间范围；
- 核心结果；
- 计划与实际差异；
- 原因和证据；
- 风险；
- 下一步、负责人和日期；
- 需要管理层决定的事项。

用下面的方式检查：

```text
根据我最初的要求建立验收清单，逐项标明最终文件中的页码、章节或工作表位置。找不到的项目写“缺失”，不要用相近内容代替。
```

## 第四步：使用预览和批注做局部修改

桌面应用可以预览文档、演示文稿、表格和 PDF。看到问题时，尽量选中或指向具体位置：

```text
这张图的标题没有说明时间范围。只把标题改成“2026 年第二季度各渠道新增客户”，数据和图表类型保持不变。
```

```text
这一段把建议写成了已经决定的事实。改成“建议方案”，保留后面的证据，不改其他章节。
```

```text
这个表格在页面中放不下。优先缩短列名和调整列宽，不删除金额、单位和来源列。
```

批注的价值是保留已经正确的部分。只有结构整体错误时才重新生成。

## Word 和普通文档怎样检查

- 标题层级是否连续，目录能否跳转；
- 页眉、页脚、页码和日期是否正确；
- 表格有没有跨页断裂或文字截断；
- 引用、脚注和链接能否定位到来源；
- 字体、行距和段落间距是否一致；
- 文档是否仍可编辑，而不是整页图片；
- 修订痕迹、批注和隐藏内容是否适合对外交付。

下载后用 Word、Pages 或接收方实际使用的软件重新打开。预览正常不代表其他软件排版完全相同。

## PPT 怎样检查

先看故事，再看美观：

1. 每页能否用一句话说出结论；
2. 页面顺序是否帮助听众做决定；
3. 数字在标题、图表和备注里是否一致；
4. 图表坐标、单位、图例和时间范围是否清楚；
5. 字号能否在投影或会议屏幕上阅读；
6. 图片、Logo、字体和模板是否有授权；
7. 每个文本框、图表和形状是否可以继续编辑；
8. 演讲备注和来源是否完整。

把全部页面渲染成图片或缩略图总览，检查是否出现重复版式、过密页面和风格突变。再随机打开三页修改文字，确认不是不可编辑的整页图片。

## Excel 和表格怎样检查

- 列名、单位、日期格式和数据范围是否一致；
- 原始数据、计算过程、假设和结果是否分开；
- 公式是否引用单元格，而不是把结果写死；
- 筛选、排序和合并单元格是否破坏数据；
- 空值、重复值和异常值怎样处理；
- 总计和分项能否对上；
- 图表是否引用正确范围；
- 改动一个输入值后，相关结果是否更新。

可以做一个简单测试：复制文件，在“假设”页修改一个已知输入，观察结果和图表是否跟着变化。测试后删除副本，不要污染正式文件。

## PDF 怎样检查

- 每页是否完整渲染，没有空白、重叠或裁切；
- 中文字体是否正常；
- 目录、书签和链接是否有效；
- 页面尺寸、方向和打印效果是否符合用途；
- 可搜索文字有没有被转成模糊图片；
- 扫描件提取是否漏掉表格、脚注和印章附近文字；
- 敏感字段有没有真正移除，而不是只用黑色方块遮住。

涉及正式脱敏时，应使用可靠的 PDF 脱敏功能并再次提取文字验证，不能只在视觉上覆盖。

## 第五步：让它做反向检查

完成局部修改后发送：

```text
请把最终文件与原始资料和最初要求做一次反向检查。

输出四部分：
1. 已满足的要求及所在位置；
2. 仍缺失或无法确认的内容；
3. 最终文件中没有来源支持的陈述；
4. 需要我在发送前人工确认的风险。

只输出检查报告，不再修改文件。
```

反向检查能帮助你发现差距，但最终决定仍由你作出。

## 第六步：在真实交付环境中打开

交付前至少做一次真实环境检查：

- Word 文件用团队常用的 Word 版本打开；
- PPT 在实际投影比例和演示模式中播放；
- Excel 在接收方使用的软件中重算公式；
- PDF 在浏览器和常用阅读器各打开一次；
- 需要打印的文件实际打印或导出打印预览；
- 需要上传平台的文件先在草稿环境测试尺寸、大小和格式。

## 常见失败

### 只看首页或第一页

错误经常藏在后续表格、备注、公式和附录里。文档逐章、PPT 逐页、表格逐工作表检查。

### 文件很漂亮，就忽略数字错误

先核事实再评视觉。金额、日期、单位和来源错误会让整个成品失去价值。

### 让它“整体再优化一次”

大范围重写会破坏已经确认的内容。用批注做局部修改，并明确哪些事实和页面不能动。

### 只确认文件存在

文件生成成功不等于能打开、能编辑或能打印。必须在真实软件和真实使用场景中复查。

## 通用交付清单

- [ ] 所有重要数字、日期、名字和承诺已对照来源。
- [ ] 必需章节、页面、字段和工作表齐全。
- [ ] 没有把建议、推断写成已确认事实。
- [ ] 生成文件已逐页或逐表预览。
- [ ] 至少完成一次局部批注修改。
- [ ] 文件在真实交付软件中正常打开并可编辑。
- [ ] 没有隐藏敏感信息、批注或错误链接。
- [ ] 发送、发布、打印或上传仍由人工执行。
