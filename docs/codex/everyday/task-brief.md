# 不会写提示词也能说清任务：普通人的任务说明法

嘿，朋友。如果你也在纠结“到底该怎么给 AI 布置任务”，那这篇文章就是为你写的。

我自己用 ChatGPT Work 和 Codex 快两年了，踩过最多的坑其实就一个：**把 AI 当搜索引擎用，一句话甩过去就期待完美结果**。后面慢慢发现，把它当成一个能力很强但对你业务一无所知的新同事，反而顺手得多。你先告诉它要交付什么，把必要资料扔过去，划几条不能碰的红线，看完草稿再继续调——这套路，我一个普通程序员都能用明白，你肯定也行。

## 最简单的任务说明

日常任务嘛，其实就回答五个问题：

1. **结果**：最终要得到什么？
2. **资料**：以哪些文件、链接、数据或事实为准？
3. **受众**：谁会阅读或使用？
4. **边界**：哪些内容不能猜、不能改、不能发送？
5. **检查**：怎样证明结果可以交付？

不一定每次都写满。我的经验是：只写那些“会改变结果”的东西，其余的不写也罢，写了反而干扰。

## 一个可以直接复制的模板

下面这个模板我平时就在用，你直接抄走：

```text
我要完成：[写清最终成品]。

使用资料：[附件、文件名、链接或已确认事实]。
使用对象：[谁会阅读、使用或做决定]。

要求：
- [长度、结构、格式、语言或风格]
- [必须保留的数字、名称、日期或品牌规则]

边界：
- 不知道的信息标为待确认，不要猜；
- 先生成草稿，不要发送、发布、付款或修改外部系统；
- 如果需要额外资料或权限，先说明原因。

完成前请检查：[最重要的 2–4 个验收点]。
```

你看，没什么花哨的。我第一次用这个模板是让 AI 帮我把三页会议纪要整理成邮件，三分钟出草稿，改了两轮就发出去了。从那以后我就再也不想手写这种活了。

## 示例一：把会议记录变成跟进邮件

```text
请把附件会议记录整理成一封会后跟进邮件，收件人是项目组成员。

邮件先写已经确认的决定，再用表格列出待办、负责人和截止时间，最后列出未解决问题。语气直接、友好，控制在 500 字以内。

只能使用记录里的事实。缺少负责人或日期时写"待确认"，不要补全。先给我邮件草稿，不要发送。完成前检查每项待办是否都有负责人和截止时间。
```

## 示例二：比较三份供应商报价

```text
根据三份附件报价制作一张可编辑比较表，供采购会议决策。

列出总价、税费、交付周期、付款条件、售后、关键差异和缺失信息。金额保持原币种，不能自行换算。另做一个摘要页，说明各方案适用情况和仍需询问的问题，不替我们做最终采购决定。

完成前逐项对照来源文件，并标出任何无法确认的数字。
```

## 示例三：制作商品页草稿

```text
使用 product-facts.xlsx 中已确认的产品事实，生成一份商品标题、五点卖点、详情页结构和客服问答草稿。

目标用户是日常通勤人群。不要使用"第一""绝对防漏""医疗级"等没有证据或容易违规的表达，不得虚构认证、销量和评价。先输出草稿与待确认清单，不要登录店铺或上架。
```

## 示例四：把故事想法变成漫剧分镜

```text
把附件故事梗概整理成一条 45 秒竖屏漫剧的节拍表和分镜表。

受众为成年短视频用户。只使用 2 个角色和 1 个主要场景，前 3 秒出现冲突，结尾留下悬念。每个镜头列出时长、画面、角色动作、台词、声音和连续性检查点。

先生成文字分镜供我审核，不生成图片、视频，不使用现有影视角色或在世艺术家的独特风格。
```

这四个例子覆盖了办公、采购、电商、内容创作四个场景。我的心得是：例子看再多不如自己动手试一次，套模板写第一条任务说明也就五分钟的事。

## 任务还不清楚时，让它先提问

说个我常犯的错：脑子里只有一个模糊想法，不好意思承认，硬凑一堆字扔给 AI，结果出来一坨自己都不想要的东西。

后来学乖了——需求不清晰的时候，直接让它来问我：

```text
我想做一份面向管理层的季度复盘 PPT，但还没有整理好要求。

请先问我最多 6 个会真正改变成品的问题，重点确认受众、会议目标、必须使用的数据、页数、品牌要求和不能公开的信息。等我回答后，再给出成品计划。现在不要生成 PPT。
```

注意，问题数量要设上限，不然它能跟你聊一下午。不确定的地方你就直说“暂未确定”，不丢人。

## 第一版不满意时，不要重新写整段提示

这个教训我交了不少学费。以前看到不满意的结果就推倒重来，把整段提示改一遍再跑——又慢又费 token。

现在我的做法特简单：盯着结果里的具体问题，一句一句纠正：

```text
开头太像背景介绍。保留事实和数据，把需要管理层决定的两件事放到第一页。
```

```text
表格里的金额正确，但缺少税费口径。只增加"含税/未税"说明，不调整数字。
```

```text
第二个方案过于激进。请保留方案一和三，重新给一个风险更低、预算不超过 5 万元的替代方案。
```

规则就一条：**说的东西能检查就行**。“更专业一点”没法验证，“把决定放前面”可以。你把注意力放在“改哪里、不动哪里”，AI 就能跟上。

## 任务运行中怎样纠偏

有时候你发现它跑偏了——别等它做完，当场喊停。这是我最想分享的一个技巧：

```text
暂停制作文件。你把内部复盘理解成了对外宣传。请先把受众改为公司管理层，保留现有资料，不要继续排版，给我新的三段结构确认。
```

我现在的习惯是：重要任务先让 AI 给个结构计划，确认了再让它动手生成文件。结构不对后面全白做，十分钟确认结构能省两小时返工。

## 用语音说任务也可以

桌面应用支持语音输入的话，你完全可以像跟同事交代工作一样口述，发之前核对一下转写内容。口述的时候按这个顺序最自然：

1. 我现在要做什么；
2. 给谁看；
3. 资料在哪里；
4. 哪些东西不能动；
5. 做完我会怎样检查。

提醒一句：人名、金额、日期和专有名词特别容易转写出错，发之前一定要校对。我有次差点把客户名字发成谐音的另一个词，还好多看了一眼——反正数字和人名，校对这一下不费事。

## 常见失败

这些坑我都替你踩过了，写出来你少走弯路。

### 一次要求十种成品

研究、PPT、文章、视频和发布计划应该拆成独立任务。先完成事实底稿，再让后续任务引用它。一口气要全部，每一样都做不扎实。

### 给了很多资料，却没说以谁为准

标明“产品事实表是唯一产品事实来源”“财务数字以已批准预算为准”。遇到冲突时要求列出差异，不自行选择。我有次三份文档给了 AI 三个不同的截止日期，它随便挑了一个，结果全错了——从那以后我每次都写明信息来源优先级。

### 把步骤写得太死

如果处理方法本身不重要，只定义成品和检查标准就好。只有法规、审批、计算口径或团队流程必须遵循时，才规定步骤。给 AI 留点发挥空间，它有时候处理得比你预想的还干净。

### 没写禁止动作

涉及邮件、社交媒体、店铺、付款、数据库或云盘时，一定要明确“先生成草稿，不发送、不发布、不修改外部系统”。这句话写上去就一行，但没写的话，万一它真的发了，你就知道什么叫心跳加速了。

## 完成门槛

- [ ] 能用一句话说出最终成品。
- [ ] 只提供会影响结果的资料。
- [ ] 说明了真实受众和使用场景。
- [ ] 重要数字、未知信息和对外动作有边界。
- [ ] 至少有两个能人工检查的完成标准。
- [ ] 第一版有问题时能提出局部、可验证的修改。
