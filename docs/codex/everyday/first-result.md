# 第一次使用 ChatGPT Work：不用写代码完成工作文件

本章用一份会议记录生成“会议结论与行动清单”。你会走完资料准备、任务说明、文件生成、预览修改、下载和人工复查，整个过程不需要打开终端或编写代码。

预计用时 20–30 分钟。不要使用真实客户隐私、未公开财务数据或账号凭证练习。

## 准备一份安全的练习资料

如果手边没有合适资料，可以把下面内容保存为 `会议记录-练习.txt`，也可以直接粘贴到任务中：

```text
7 月 11 日新品上线会

目标：确认试用活动的上线准备。
决定：活动先开放给 100 名老客户，报名页计划 7 月 18 日上线。
待办：小周确认报名字段；小林准备客服问答；阿杰检查库存。
问题：最终优惠额度还没有批准；客服值班时间未确认。
下次检查：7 月 15 日下午。
```

这份资料故意留了两处未确认信息。好的结果应该把它们标成问题，而不是替你编答案。

## 第一步：选择 Work

打开 ChatGPT 桌面应用，选择 **Work**，然后新建任务。

- 如果只是问一个问题或改写两句话，用 Chat 即可。
- 如果要完成可下载文件、需要多个步骤或需要反复检查，优先用 Work。
- 如果你的版本暂时没有 Work，但已经可以用 Codex 做非编程任务，可以沿用本章提示；界面名称可能不同，核心步骤仍是“给资料—出草稿—预览—修改—复查”。

这个练习是一次性结果，不需要先创建项目。等同一主题会持续几周时，再学习 [项目与文件管理](/codex/everyday/projects-files)。

## 第二步：附加资料

把 `会议记录-练习.txt` 拖入输入框，或使用附件按钮选择它。

发送前确认：

- 文件名正确；
- 没有多选私人文件；
- 练习资料里没有真实手机号、身份证、账号、密码或未公开商业信息；
- 你知道这次任务只需要会议记录，不需要整个文件夹。

## 第三步：直接说明成品

复制下面的任务说明：

```text
请根据附件制作一份一页的会议结论与行动清单，供项目组会后确认。

成品需要包含：
1. 已确认的决定；
2. 待办事项表，列出事项、负责人、截止时间和状态；
3. 尚未确认的问题；
4. 下次检查时间。

规则：
- 只能使用附件中的事实；
- 没写负责人或日期的地方标为“待确认”，不要猜测；
- 先生成可预览的文档草稿，不要发送给任何人；
- 完成前检查每一项待办是否有负责人和截止时间，并列出缺口。
```

你不必把每个处理步骤都规定出来。你只需要说清结果、读者、资料、不能做什么，以及怎样算完成。

## 第四步：观察过程，但不要盲目批准

任务运行时可能显示计划、使用的资料、生成文件和需要你回答的问题。

如果它问“没有截止时间怎么办”，回答：

```text
保留“待确认”，不要自行补日期。
```

如果出现发送邮件、访问其他应用、连接云盘或读取额外文件的请求，本章都不需要，选择拒绝或取消。生成本地草稿不等于允许它对外发送。

## 第五步：打开预览逐项检查

文件生成后，不要只看“已完成”。打开预览，依次检查：

1. 决定是否准确写成“先开放给 100 名老客户”；
2. 报名页日期是否仍是 7 月 18 日；
3. 小周、小林、阿杰的事项有没有串人；
4. 优惠额度和客服值班时间是否标成未确认；
5. 没有凭空增加预算、负责人或承诺；
6. 页面是否清楚，表格有没有文字被截断。

## 第六步：用批注做局部修改

如果标题太长，选中标题或指向预览中的对应位置，发送：

```text
只把这个标题改成“新品试用活动会议行动清单”。其他内容和数据保持不变。
```

如果表格缺少状态列，指向表格后发送：

```text
给这个表格补一列“状态”。已明确的事项写“待执行”，信息不完整的写“待确认”。不要改负责人和日期。
```

局部反馈比“重新做得好看一点”更容易保留已经正确的部分。

## 第七步：下载并用常用软件再打开

下载生成文件，保存为容易识别的名称，例如：

```text
新品试用活动-会议行动清单-v1.docx
```

再用 Word、Pages 或交付方实际使用的软件打开，检查：

- 文件能正常打开；
- 中文字体和分页没有变化；
- 表格仍能编辑；
- 文件名、版本和保存位置清楚；
- 没有覆盖原始会议记录。

如果当前能力只能生成文本而不能生成 `.docx`，先让它输出结构清楚的最终文本，再复制进 Word。不要为了得到文件格式去安装来历不明的工具。

## 第八步：做最后一次对照

把最终文件和原始记录一起交给任务，发送：

```text
请逐项对照原始会议记录和最终文档，列出：
1. 完全一致的事实；
2. 文档中新增但原始记录没有的内容；
3. 原始记录有但文档遗漏的内容；
4. 仍需人工确认的地方。

只做检查，不修改文件。
```

自己再看一遍检查结果。AI 的自检可以发现遗漏，但不能替代你的最终责任。

## 常见失败

### 结果只是一段聊天文字

补充：“请创建一个可下载、可继续编辑的文档，并在完成后打开预览。”如果当前账户没有对应文件能力，就接受文本草稿并手动放入 Word。

### 它补出了不存在的截止日期

明确要求：“删除所有没有来源的日期，并把缺失值写成待确认。”以后在任务开头加入“未知信息不得猜测”。

### 改标题时把正文也重写了

使用预览批注，明确“只修改选中部分，其他内容和数据保持不变”。

### 下载后排版变了

说明最终使用的软件和字体环境，再生成一版；仍需在真实交付软件中检查，预览正确不代表所有电脑都一致。

## 完成门槛

- [ ] 全程没有使用终端或代码。
- [ ] 成品中的事实能回到原始资料。
- [ ] 未确认信息没有被模型补全。
- [ ] 至少完成一次局部批注修改。
- [ ] 文件已下载并在常用软件中打开。
- [ ] 没有发送、发布或覆盖原始文件。
