# 第一次使用 ChatGPT Work：不用写代码完成工作文件

你好啊，我是小枫同学。

这一章我们一起来做一件事：把一份会议记录，变成一份干干净净的"会议结论与行动清单"。整个过程不用打开终端、不用写一行代码，只需要点点鼠标、打打字。你跟着走一遍，大概 20 到 30 分钟。

提醒一句：练习的时候别用真实客户隐私、未公开财务数据或者账号密码，拿一段自己编的内容就好。

## 准备一份安全的练习资料

手边没有合适的会议记录？没关系，把下面这段保存成 `会议记录-练习.txt`，或者直接复制粘贴到任务里也行：

```text
7 月 11 日新品上线会

目标：确认试用活动的上线准备。
决定：活动先开放给 100 名老客户，报名页计划 7 月 18 日上线。
待办：小周确认报名字段；小林准备客服问答；阿杰检查库存。
问题：最终优惠额度还没有批准；客服值班时间未确认。
下次检查：7 月 15 日下午。
```

你注意到没，这份记录里故意留了两个没敲定的事——优惠额度和值班时间。一个好的 AI 输出，应该老老实实把它们标成"待确认"，而不是自己瞎编一个答案填上去。这也是我们后面检查时要盯住的地方。

## 第一步：选择 Work

打开 ChatGPT 桌面应用，点 **Work**，然后新建一个任务。

怎么判断用 Chat 还是 Work？我的习惯是这样的：

- 就问一个问题、改几句话——Chat 足够了。
- 要出一个可下载的文件、涉及好几个步骤、或者需要反复核对——Work 更合适。
- 如果你的版本暂时还没 Work，但有 Codex 能做非编程任务，这一章的提示词一样能用。界面名字可能不一样，但核心流程不变：给资料 → 出草稿 → 预览 → 修改 → 复查。

这次的练习是一次性任务，不需要先建项目。等同一主题要持续跟进好几周的时候，再去翻 [项目与文件管理](/codex/everyday/projects-files) 也不迟。

## 第二步：附加资料

把 `会议记录-练习.txt` 拖进输入框，或者点附件按钮选它。

发送之前，花 5 秒确认这几件事：

- 文件名没错；
- 没多选私人文件；
- 练习资料里没有真实手机号、身份证、账号、密码或者未公开的商业信息；
- 你清楚这次任务只需要这一份会议记录，不需要整个文件夹。

我刚开始用的时候踩过一个坑：拖文件拖太快，把一个包含客户信息的文件夹整个扔进去了。还好及时发现取消了——所以这个习惯我现在每次都做，养成肌肉记忆就好。

## 第三步：直接说明你要什么成品

把下面这段任务说明复制进去：

```text
请根据附件制作一份一页的会议结论与行动清单，供项目组会后确认。

成品需要包含：
1. 已确认的决定；
2. 待办事项表，列出事项、负责人、截止时间和状态；
3. 尚未确认的问题；
4. 下次检查时间。

规则：
- 只能使用附件中的事实；
- 没写负责人或日期的地方标为"待确认"，不要猜测；
- 先生成可预览的文档草稿，不要发送给任何人；
- 完成前检查每一项待办是否有负责人和截止时间，并列出缺口。
```

你看，我没写"第一步做什么、第二步做什么"那种操作手册。你只需要说清楚：最终成品长什么样、给谁看、依据什么资料、不能做什么、怎么样算完成。AI 自己能处理好中间的步骤。

## 第四步：观察过程，但别盲目点批准

任务跑起来的时候，可能会显示它的计划、用到的资料、正在生成文件，也可能弹出问题问你。

如果它问"没有截止时间怎么办"，这样回：

```text
保留"待确认"，不要自行补日期。
```

如果它提出要发邮件、访问其他应用、连云盘、或者读额外的文件——这一章全都不需要，直接拒绝或者取消。记住，生成本地草稿和让它对外发送，完全是两回事。

## 第五步：打开预览逐项检查

文件生成之后，别看到"已完成"三个字就关了。打开预览，一项一项过：

1. 决定有没有准确写成"先开放给 100 名老客户"；
2. 报名页日期是不是还写着 7 月 18 日；
3. 小周、小林、阿杰各自负责的事有没有搞混；
4. 优惠额度和客服值班时间有没有老老实实标成未确认；
5. 有没有凭空多出来预算、负责人或者承诺——这很关键；
6. 页面看着清不清楚，表格里有没有文字被截断。

## 第六步：用批注做局部修改

如果标题太长了，选中标题或者在预览里指到对应位置，发送：

```text
只把这个标题改成"新品试用活动会议行动清单"。其他内容和数据保持不变。
```

如果表格少了状态列，指向表格后发送：

```text
给这个表格补一列"状态"。已明确的事项写"待执行"，信息不完整的写"待确认"。不要改负责人和日期。
```

我自己的经验：局部反馈比说一句"重新做得好看一点"靠谱太多了。后者很容易把前面已经对的也给改了，得不偿失。

## 第七步：下载并用常用软件再打开一次

下载生成的文件，起一个一眼就能认出来的名字，比如：

```text
新品试用活动-会议行动清单-v1.docx
```

然后用 Word、Pages 或者你交付对象实际用的软件打开，再检查一轮：

- 文件能正常打开；
- 中文字体和分页没跑偏；
- 表格还能编辑；
- 文件名、版本号、保存位置都清楚；
- 没有覆盖掉原始会议记录。

如果当前能力只能出纯文本、生成不了 `.docx`，没关系——先让它输出结构清楚的最终文本，再手动复制进 Word。千万别为了搞个文件格式去装来路不明的工具，不值当的。

## 第八步：做最后一次对照

把最终文件和原始记录一起丢给任务，发送：

```text
请逐项对照原始会议记录和最终文档，列出：
1. 完全一致的事实；
2. 文档中新增但原始记录没有的内容；
3. 原始记录有但文档遗漏的内容；
4. 仍需人工确认的地方。

只做检查，不修改文件。
```

AI 自查完，你自己再过一遍结果。说实话，AI 的自检能帮你发现不少遗漏，但它永远不能替你承担最终责任——最终拍板的人还是你。

## 常见翻车现场

这些是我自己或者朋友碰到过的情况，提前说一下，省得你再踩一遍。

### 结果只是一段聊天文字

补一句："请创建一个可下载、可继续编辑的文档，并在完成后打开预览。"如果当前账户确实没有文件生成能力，那就接受文本草稿，手动放进 Word。

### 它补出了不存在的截止日期

明确要求："删除所有没有来源的日期，并把缺失值写成待确认。"以后养成习惯，在任务开头就加上"未知信息不得猜测"。

### 改标题时把正文也重写了

用预览批注，说清楚"只修改选中部分，其他内容和数据保持不变"。这句话加和不加，效果差很多。

### 下载后排版变了

说明你最终使用的软件和字体环境，再让它生成一版。即使预览看着没问题，也要在真实交付软件里打开确认——预览正确不等于每台电脑都一致。

## 完成门槛

- [ ] 全程没有使用终端或代码。
- [ ] 成品中的事实能回到原始资料。
- [ ] 未确认信息没有被模型补全。
- [ ] 至少完成一次局部批注修改。
- [ ] 文件已下载并在常用软件中打开。
- [ ] 没有发送、发布或覆盖原始文件。
