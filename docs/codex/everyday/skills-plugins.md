# 普通人怎样使用 ChatGPT Skill 和 Plugin

Skill 和 Plugin 不是程序员专属。对普通用户来说，Skill 像一份会自动执行的标准工作手册，Plugin 像一个可以安装并连接其他工具的能力包。它们能减少重复解释，但不会自动保证内容正确或数据安全。

## 用一句话区分

- **Skill**：告诉 ChatGPT“这类工作应该按什么步骤、模板和标准完成”。
- **Plugin**：安装一组能力，可能包含 Skill，也可能连接 Google Drive、Slack、邮件、CRM 等外部服务。

例如：

- “每周经营简报 Skill”规定数据来源、指标口径、页面结构和检查清单；
- “Google Drive Plugin”让任务在授权范围内查找云盘资料；
- “演示文稿 Skill”帮助生成、渲染和检查 PPT；
- “电商运营 Plugin”可能连接店铺数据或提供平台工作流。

## 先用内置能力，不急着安装

第一次使用时，优先查看当前账户已经提供的能力，例如：

- 文档、演示文稿、表格和 PDF；
- 网页研究和浏览；
- 图片生成或编辑；
- 数据分析与可视化；
- 文件预览和批注；
- Skill Creator 或类似的 Skill 创建能力。

不同版本、套餐、操作系统和工作区策略提供的列表可能不同。以输入框和能力列表中实际显示的项目为准，不要因为教程提到某个名称就从陌生网站下载同名文件。

## 怎样调用 Skill

最简单的方式是直接描述工作，ChatGPT 会在匹配时选择 Skill。也可以在输入框显式选择：

- Codex 中通常使用 `$` 提及 Skill；
- ChatGPT / Work 中可以从输入框的能力选择器中选择，当前官方资料也支持相应的提及方式；
- Plugin 通常可通过 `@` 选择具体插件或连接来源。

界面可能随版本变化。如果输入符号没有出现列表，打开 Skills 或 Plugins 页面查看当前可用项，不要反复输入未知命令。

## 第一次使用 Skill 的安全流程

以“制作 PPT”为例：

1. 先在普通任务里准备资料和页级故事线；
2. 查看当前是否有演示文稿或文件 Skill；
3. 显式选择它，并说明需要可编辑 `.pptx`；
4. 限制它只使用已附加资料；
5. 要求先出草稿，不分享、不发送；
6. 打开预览逐页检查；
7. 下载后用 PowerPoint 再打开；
8. 记录这次有效的输入和修改方法。

Skill 负责稳定流程，你仍负责业务事实和最终批准。

## 一个普通人可用的 Skill 提示

```text
请使用当前可用的演示文稿能力，把附件资料制作成 8 页项目复盘 PPT。

受众是管理层。先给出页级故事线，等我确认后再生成文件。所有数字必须标明来源文件，建议和已确认事实分开。PPT 需要可编辑，生成后逐页渲染检查，并告诉我仍需人工确认的内容。

不要发送、分享或上传到外部平台。
```

## Plugin 连接外部工具前看什么

安装或授权前回答六个问题：

1. 它由谁提供，来源和维护状态是否清楚？
2. 它会读取哪些资料？
3. 它只能读取，还是也能创建、修改、发送或删除？
4. 授权范围能否缩小到一个文件夹、频道或测试账号？
5. 数据会发送到哪里，是否符合公司政策？
6. 不再使用时怎样撤销授权和删除连接？

“能安装”不等于“适合接入真实客户数据”。先在虚构或脱敏资料上试用。

## 适合普通用户的 Skill 类型

### 办公文件

用于 Word、PPT、Excel 和 PDF 的创建、编辑、渲染和检查。优先选择能生成可编辑文件并提供预览的能力。

### 研究与来源整理

用于网页搜索、资料比较、引用台账和报告。必须要求来源链接、日期、事实与分析区分。

### 品牌与内容规范

把品牌名称、语气、禁用词、渠道格式和审查清单固定下来。不要把单篇文章的内容写死在 Skill 中。

### 周报和会议跟进

适合输入、结构和输出长期稳定的重复工作，例如每周状态更新、会议行动项和经营简报。

### 电商和运营

可以固定产品事实表、Listing 格式、详情页结构、客服草稿和数据复盘口径。上架、改价、投流和退款必须保留人工审批。

## 不要一次安装很多

选择一个月内会实际使用的 3–5 个能力即可。每增加一个 Skill 或 Plugin，都记录：

- 名称和来源；
- 用于什么任务；
- 接触哪些资料；
- 是否能执行外部写操作；
- 谁批准安装；
- 最近一次验证日期；
- 如何停用或撤销授权。

列表越长，越难知道某个任务究竟调用了什么。

## 不写代码也能创建自己的 Skill

先选择一个已经手动成功至少三次的任务，例如“每周项目更新”。新建任务并发送：

```text
请帮我创建一个“每周项目更新” Skill。

每次输入：本周会议记录、任务清单和风险说明。
固定流程：先核对日期和负责人，再整理进展、风险、决定和下周事项。
固定输出：一页管理层摘要和一封团队邮件草稿。
必须检查：每个行动项有负责人和日期；没有来源的信息标为待确认。
禁止动作：不发送邮件，不修改任务系统，不读取未附加资料。

请先向我确认缺失规则，再生成可测试的 Skill 草稿和三条测试用例。
```

检查草稿是否写清：什么时候触发、需要什么输入、按什么步骤做、输出什么、怎样检查、什么事情不能做。

如果需要把 Skill 作为文件安装、共享给团队或加入脚本，再进入开发者版的 [从零创建自己的 Skill](/codex/skills/create)。普通用户不必一开始就手工编写 `SKILL.md`。

## 用真实样本测试

至少测试三种情况：

1. 正常资料齐全；
2. 缺少日期或负责人；
3. 用户要求它直接发送或发布。

好的 Skill 应在第一种情况完成成品，在第二种情况标出缺口，在第三种情况停在草稿和人工批准前。

## 常见失败

### 把一次提示词直接叫 Skill

Skill 应包含稳定步骤、模板、资源和检查标准。只使用一次的任务继续保留为普通任务即可。

### 认为官方或热门等于没有风险

仍要查看它能访问什么、能执行什么，以及是否适合公司的数据政策。

### Skill 结果不对，就不断增加长规则

先判断是资料不足、触发错误、步骤遗漏还是输出模板有问题。规则过长会让真正重要的边界更难发现。

## 完成门槛

- [ ] 能用白话区分 Skill 和 Plugin。
- [ ] 会从当前应用实际可用列表选择能力。
- [ ] 连接外部工具前会检查读写范围和撤销方式。
- [ ] 至少用一个 Skill 完成并检查真实文件。
- [ ] 不会为了“功能更多”一次安装大量能力。
- [ ] 能用自然语言制作一个简单 Skill 草稿并测试边界。
